## Requirements engineering (`docs/`)

The `docs/` layout is identical across all four projects — Maschinell,
PositiveParentingReminders, lieferkarte-karlsruhe, BauWatch-KA. It separates by
rate of change:

| Layer | Path | Rate of change |
|---|---|---|
| Why & what | `docs/PRD.md` | rarely |
| How it was decided | `docs/entscheidungen/` | **append-only** |
| What's next | `docs/anforderungen/` | fluid |
| Technical tasks | `docs/BACKLOG.md` | fluid |
| What's shipped, and why that way | `docs/UMGESETZT.md` | grows |
| Implementation spec | `docs/TECHNICAL.md` | with the code |

- **Requirements go through `docs/PROZESS.md`, not straight into code.** A non-trivial idea — even phrased as a question („Können wir X?") — gets refined first: survey the code, name the tensions with the non-goals in `docs/PRD.md`, lay out options with a recommendation, let the product owner decide the open questions, then **its own file** `docs/anforderungen/A-<n>-<kurz-titel>.md` (from `_vorlage.md`) — or, if the idea already has a row or a stub file, *that* file reshaped into the template's form, keeping its number — plus a row in `docs/anforderungen/README.md` (status lives **only** there). **Implementation only on explicit green light** — a pre-assigned branch name is not one. „Impl A-\<n>" / „setz das um" **is** that green light for building, but not a licence to skip the refinement: run it first in the same session, put the open decisions to the product owner with measured numbers (`AskUserQuestion`), then build. A stub that was never refined has no Definition of Done to build against. The `/anforderung` slash command runs the process.
- **The `Ausgangstext` of an unrefined requirement predates the shipped ones — measure, don't adopt.** Every remaining `A-…` stub quotes `backlog/IDEEN.md` from before A-1, so its element counts, pixel figures and screen percentages describe a UI that no longer exists. Re-measure against the current `web/index.html` (Playwright with the `L` stub), keep the original as a quoted block, and name the corrections visibly instead of silently carrying the old numbers into the spec. **This applies to a freshly refined spec too, not just stubs** — recompute its figures before building on them even if it was committed a day earlier. Three of A-4's contrast values did not reproduce (8,78→12,52 · 1,65→1,21 · 2,00→2,85) while every number in its ADR did; all three happened to fall in the decision's favour, which is luck, not a reason to trust them. Verify first, then strike the wrong ones with `~~…~~` plus the measured value. **The same rot affects numbers baked into UI strings** — the two filter hints still read „nur 7 % sind überhaupt getaggt" / „26 % getaggt" from an older scan. Any share or count shown to users belongs in code that computes it from the loaded data, not in the German text.
- **„Jetzt geöffnet" exists only in JavaScript.** `openStateNow()` in `web/index.html` is the single implementation and deliberately conservative ([ADR-004](docs/entscheidungen/ADR-004-oeffnungszeiten-eigener-parser.md)); neither `scanner.py` nor `export.py` knows the state. Any spec needing open/closed/unknown counts must evaluate *that* function against `web/restaurants.json` in Playwright — a second parser in Python would drift from its rules and quietly produce different numbers. Measured 2026-07-26 midday: 427 open · 248 closed · 210 not evaluable (143 of them without `opening_hours` at all).
- **Finishing a requirement drifts documents outside `docs/anforderungen/`.** The root `README.md` keeps its own „Bereits umgesetzt"/„Offen" lists and was **two requirements behind** when A-5 landed (A-3 and A-4 shipped without it), and an ADR's status lives in **two** places — the `Status:` header in the file and the row in `docs/entscheidungen/README.md` (ADR-008's row still said `vorgeschlagen` while the file said `akzeptiert`). Check both, plus `docs/UMGESETZT.md`, before setting the status to 🏁.
- Small fixes and technical chores go straight into `docs/BACKLOG.md`; the dividing line is in the process file („Anforderung oder Aufgabe? Der Test").
- **A decision that goes against the requirement's own recommendation gets documented, not smoothed over.** Raise the conflict once, with numbers from the DB; if the product owner reaffirms, build exactly that. Then record the choice *and the rejected recommendation* in the requirement file, strike invalidated Definition-of-Done lines with `~~…~~` plus their replacement instead of deleting them, and write an ADR whenever the decision fixes a lasting product stance ([ADR-007](docs/entscheidungen/ADR-007-standardfilter-liefert-jetzt.md) is the worked example). **Two Definition-of-Done lines can contradict each other once you measure, too** — A-3 wanted a one-line mobile footer carrying attribution + date + privacy link at ≥ 0,8 rem *and* `#map` ≥ 95 %; at 360 px that is 369,3 px of text on 337,6 px of space. Resolve by keeping whichever line is externally hard (the ODbL attribution) or has no second home in the UI, strike the other with the measured numbers, and say so — never quietly miss a number.
- Architectural decisions become an ADR in `docs/entscheidungen/`. That folder is **append-only** — the prose is never rewritten; the only permitted edits are status transitions (`vorgeschlagen` → `akzeptiert` once the decision is built, or `ersetzt durch ADR-<Nr>` when a later ADR reverses it).
- **Raw ideas need no file**, just a row in the overview table with status `💡 Idee`.
- **A-1 (Standardfilter) is decided and shipped** ([ADR-007](docs/entscheidungen/ADR-007-standardfilter-liefert-jetzt.md), 2026-07-25): the default filter is **„Liefert jetzt"** — `delivery` **and** currently open, ~35 of 883 at midday and zero at night, deliberately narrower than before. The map is a *Jetzt-Werkzeug, kein Verzeichnis*. Read the ADR before touching `FILTER_DEFAULTS`; widening the default back out is a reversal that needs a new ADR, not an edit. A-8 (filters in the URL) shipped with it. The three requirements A-1 blocked are unblocked: A-8 shipped with A-1 itself, and A-5 (pins) shipped on 2026-07-26 on top of A-4's tokens but was reverted the same day (ADR-011). A-6 (clustering) dropped back to „nice to have" because 885 markers only render when the user clears the filters — A-5 had briefly made it a one-line `preferCanvas: true`, but with the vector pins gone it is real work again.

> Until 2026-07-25 the backlog lived in `backlog/`, split into three stage files (`IDEEN.md` → `READY-FOR-DEV.md` → `DONE.md`). Those are dissolved: a status change is now one word in the overview table instead of moving text between files, which is what previously forced the special rules about relative links and stable numbering. `DONE.md` became `docs/UMGESETZT.md` unchanged. The `R…`/`P…` labels from the July 2026 UI/UX review are preserved throughout.

**Data source: OpenStreetMap via the Overpass API** (not Google Places). This was a deliberate switch: Google's Maps Platform terms forbid storing paid Places data >30 days, redistributing it, or showing it off a Google map — all of which a public repo with a committed DB/JSON would do. OpenStreetMap is under the **ODbL**, which explicitly permits public (even commercial) redistribution as long as "© OpenStreetMap-Mitwirkende" attribution is shown. That makes the public-repo model licit and free.

`docs/TECHNICAL.md` is the implementation spec — the DB schema, the Overpass query, change-detection rules. Read it (and verify against the actual files) before changing pipeline code.

## Language

The project and all docs are in **German** (it's a public service for Karlsruhe). Keep user-facing strings, commit messages, and new docs in German to match; code identifiers follow the existing docs (e.g. `sync_places`, `normalize_osm`, `fetch_overpass`).

## Architecture (as specified in docs/TECHNICAL.md)

A weekly batch pipeline, no backend server. Data flows one direction:

```
scanner.py  ──> data/restaurants.db ──> export.py ──> web/restaurants.json ──> web/index.html
(Overpass API)   (SQLite)                (DB→JSON)                              (Leaflet map + PWA)
```

- **scanner.py** — queries the Overpass API (OpenStreetMap) in a single request, upserts into SQLite keyed on `place_id` (an OSM `type/id`, e.g. `node/12345`), and detects changes vs. the previous scan.
- **SQLite schema** — three tables: `restaurants` (current state, `place_id` = stable key), `changes` (append-only log: `NEW` / `REMOVED` / `ADDRESS_CHANGED` / `DELIVERY_CHANGED` / `TAKEAWAY_CHANGED` / `STATUS_CHANGED`), `scan_runs` (per-scan timestamp + request count).
- **export.py** — reads the DB, writes `web/restaurants.json` (`{count, generatedAt, ...}`); the workflow's summary step reads those fields via `jq`. It also builds the `feed` block for the „Diese Woche neu"-Panel (`build_feed()`): the `changes` of the last 7 days, **minus the initial import** (the first scan logs every restaurant as `NEW`), capped per change type. Rules documented in `docs/TECHNICAL.md`.
- **web/** — static Leaflet + OpenStreetMap map. Both the map tiles and the restaurant data come from OpenStreetMap (ODbL), so a single "© OpenStreetMap-Mitwirkende" attribution covers everything.
- **PWA (`web/sw.js` + `web/manifest.webmanifest`)** — installable and offline-capable, no build step. Paths are relative (`./…`) because Pages serves the site from `/<repo>/web/`. Details in `docs/TECHNICAL.md` ("PWA"); design rationale in `docs/UMGESETZT.md` and `docs/entscheidungen/ADR-006-pwa-network-first.md`.
- **Deployment** — GitHub Pages serves from `main` at repo root, so `web/` assets and the JSON are committed into the repo. The DB is also committed (its history *is* the change log — see `fetch-depth: 0` in the workflow). Under ODbL this is fine; it would have breached Google's terms.

## Commands

```bash
python3 -m unittest discover -s tests -v   # run the test suite (stdlib only, no install)
python3 scanner.py             # full scan via Overpass: upsert + change + REMOVED detection
python3 scanner.py --light     # refresh without REMOVED detection
python3 export.py              # regenerate web/restaurants.json from the DB
python3 tools/make_icons.py    # regenerate web/icons/*.png (only if the icon design changes)
cd web && python3 -m http.server 8000   # preview at http://localhost:8000
```

The preview must run over `http://localhost` (not `file://`) — service workers
need a secure context. Check the PWA in DevTools → Application (Manifest,
Service Workers, Cache Storage) and test offline via Network → "Offline".

**Run the tests before pushing any pipeline change.** They use in-memory/temp databases and never touch `data/restaurants.db`; there is no linter configured.

**`export.py` does not migrate the DB.** After adding a column, `init_db()` has to run against the committed `data/restaurants.db` once (`python3 -c "import sqlite3, scanner; c = sqlite3.connect('data/restaurants.db'); scanner.init_db(c); c.close()"`), otherwise a local `python3 export.py` fails on the missing column. In CI this can't happen — the workflow runs `scanner.py` (which migrates) first.

**There is no mock mode.** `scanner.py --mock` and its demo rows were removed once real data replaced them (mock counted as a full scan and would have marked every real restaurant as REMOVED). The scanner only knows full and `--light`; the tests seed their fixtures directly via `sync_places` into temp DBs (`tests/helpers.py`).

## Working in a sandboxed session (Claude Code on the web)

The network policy of a web session blocks both external hosts this project uses, so plan verification accordingly:

- **Overpass is unreachable** (the proxy answers 403 to the CONNECT). No real scan is possible — `python3 scanner.py` will abort by design (and that's the correct behaviour: it leaves the DB untouched). Verify pipeline changes with the unittest suite instead; new columns stay `NULL` until the next Sunday workflow run fills them. Say so plainly rather than implying the data was refreshed.
- **The Leaflet CDN (unpkg) is unreachable**, so `web/index.html` cannot render a real map here — the page hangs at "Lade Restaurants …" because `L` is undefined. To test frontend logic, copy the page into a scratch dir, replace the two unpkg tags with a tiny `L` stub (`map` incl. `setView`/`removeLayer`, `tileLayer`, `layerGroup` incl. `clearLayers`, `marker`, `circleMarker`, and a chainable `popup` with `setLatLng`/`setContent`/`openOn` — `focusPlace()` and `locateMe()` need those two, and a stub without them throws on the first feed click) that collects the markers in `window.__markers`, serve the dir with `python3 -m http.server` and drive it with Playwright. Filter counts (`#count`), option lists and popup HTML are all assertable that way; test both with synthetic data **and** with the real `restaurants.json` (untagged fields must degrade gracefully). **Load the page with `?delivery=0&open=0`**, or the default „Liefert jetzt" filter hides most of the fixture (53 of 885 rendered when measured on 2026-07-26 in the early evening) and the assertions quietly measure the wrong set. **`bindPopup` receives a *function*, not a string** (popups are built lazily — R7): the stub must store it and the assertion must call it, otherwise every popup reads as `undefined`. To exercise `locateMe()`, replace `navigator.geolocation` via `Object.defineProperty` (plain assignment fails silently) and give the marker stub `openPopup` — the call chains `.addTo(map).bindPopup(…).openPopup()`. The stub has no `L.DomEvent`, so any code path that calls it is untestable here — one more reason to keep overlay/control DOM a *sibling* of `#map` rather than a child, where Leaflet never sees its events in the first place. Since A-3 the stub also needs a **`.leaflet-control-attribution` element inside `#map`** (bottom right), or you cannot check that `#mapControls` clears it. The stub must **record the second argument of both `marker` and `circleMarker`** and which of the two was called: since ADR-011 the assertion runs the other way round — every restaurant pin has to be an option-less `L.marker`, and `L.circleMarker` may only appear for `locateMe()`. A stub that stores just coordinates cannot tell those apart and makes the check vacuous in either direction. Two things the stub cannot do: it never draws, so pin *appearance* is not checkable here at all (that blind spot is what got A-5 reverted — see the pin bullet below), and contrast has to be **computed** from the tokens, not sampled from pixels. When measuring `render()`, warm up first (20 runs, then take the median of 20): un-warmed calls come out ~10× slower and produce figures that look like a regression where there is none — that trap turned a real 0,4 → 5,6 ms into an apparent 3 → 53 ms. **Assert on layout, not only on state** — three A-3 defects (a click-through sheet, a dead ✕, a grip rendered as a white 14-rem box) were invisible to `hidden`/`aria-*` assertions; `elementFromPoint` at an element's centre, `getBoundingClientRect` overlap, and an actual screenshot each caught one. And **take the screenshot** — the specificity bug survived 145 passing checks.
- **Chromium is preinstalled** under `/opt/pw-browsers` — do not run `playwright install`. A freshly npm-installed `playwright` may expect a newer build than the image ships, so launch with `executablePath` pointing at the existing `chromium-*/chrome-linux/chrome`.

## Constraints that drive the design

These are the hard rules. Most of them now also exist as ADRs in
`docs/entscheidungen/` with full context, rejected alternatives and consequences —
this list stays as the quick reference.

- **Free and republishable is the whole point.** ([ADR-001](docs/entscheidungen/ADR-001-openstreetmap-statt-google-places.md)) The move off Google Places was to make a *public* repo licit (see top). Don't reintroduce a data source that forbids public redistribution or requires paid per-call SKUs. Overpass is free; be a good citizen (single request per scan, descriptive `User-Agent`, backoff on 429/5xx).
- **Never let an empty/failed scan wipe the DB.** ([ADR-003](docs/entscheidungen/ADR-003-scan-darf-db-nie-leeren.md)) A full scan marks not-seen restaurants as REMOVED. `scanner.py` therefore aborts (leaves the DB untouched) if Overpass fails or returns zero usable places — preserve this guard in any refactor.
- **`--light` mode intentionally does not mark REMOVED.** An incomplete Overpass response must not delete entries; removals are only trusted from the full scan. Preserve this asymmetry.
- **`delivery` (Lieferung) and `takeaway` (Abholung) come from the OSM tags of the same name** (`yes`/`only` → true, `no` → false, untagged → unknown/`NULL`), parsed via `_osm_yesno`. Both are separate, independent tags. Coverage is patchy (most restaurants are untagged) — the frontend must handle `delivery === null` / `takeaway === null` gracefully. Each has its own filter chip, and `null` is **never** rendered as „nein": the popup shows an explicit „unbekannt" badge (ADR-007).
- **`cuisine` (Küchenstil) is normalized in the scanner** (`_osm_cuisine`): the OSM tag allows multiple values in arbitrary spelling (`pizza;italian`, `Ice Cream`, `coffee-shop`) → the DB column holds a canonical `;`-separated list of lowercase keys (`NULL` = untagged); junk values (`yes`/`no`/`unknown`/`fixme`/`other`) and duplicates are dropped. `export.py` emits it as the list `cuisines` (empty list = unknown); the German labels live in the frontend (`CUISINE_LABELS`), the DB stays raw. The frontend's filter dropdown is built from the values actually present and stays hidden while none are tagged. Cuisine changes are deliberately **not** logged in `changes` ([ADR-005](docs/entscheidungen/ADR-005-cuisine-nicht-protokollieren.md)).
- **The `changes` table has two traps — anything that reads it must handle both.** (1) The **initial import**: the first scan logged all 883 restaurants as `NEW` on a single timestamp. That's the starting inventory, not news — `build_feed()` drops everything at the first `scan_runs` timestamp. (2) **Mass events when a column is introduced**: the scan that first read the existing `takeaway` tags logged 245 × `TAKEAWAY_CHANGED` ("unbekannt → ja") at once. The feed therefore caps items per change type (`FEED_MAX_PER_TYPE`) and reports the true number in `counts`. Any *new* change type will cause the same burst on the scan that first reads the tag — which is one reason `cuisine` deliberately logs nothing. A new type also has to be registered in **two** places: `FEED_TYPE_ORDER` (`export.py`) and `FEED_GROUPS` (`web/index.html`) — otherwise the panel shows the raw type string as its group heading.
- **Colour has three separated roles — brand, interaction, data state — and none borrows another's value.** ([ADR-009](docs/entscheidungen/ADR-009-farbrollen-marke-aktion-zustand.md), shipped with A-4 on 2026-07-25) `--accent` and `--ok` **no longer exist**; seeing either in a patch is a regression, and a missed `var(--accent)` fails *silently* (the browser falls back to `initial`). The set is `--marke` (brand only, never a state) · `--aktion`/`--aktion-hover`/`--aktion-schwach` (links, buttons, active chips) · `--zustand-ja`/`-nein`/`-unbekannt` plus `-bg` pairs (data state). **No colour value outside `:root`** — the only exceptions are the three `theme-color` metas and `manifest.webmanifest`, where `var()` is impossible; in JS use `cssVar(name, fallback)`. Three rules bind: colour carries the *state*, the symbol carries the *capability* (so „🥡 Abholung" is green like „✔ Lieferservice", and blue is spent); colour **alone** never encodes a state (ja↔nein are only 1,92 apart — symbol, shape or text must come along); and „unbekannt" separates from „nein" by **shape**, not hue (filled vs. dashed outline) because it is the *most common* state at 87,5 % and must never read as a refusal ([ADR-007](docs/entscheidungen/ADR-007-standardfilter-liefert-jetzt.md)). **When shape carries the state, the shape needs contrast too** — 3:1 per WCAG 1.4.11, not just the text: the dashed outline uses `--zustand-unbekannt` (5,33:1), not `--border` (1,15:1, effectively invisible), which would have left the mechanism nominally present and practically useless. Badge classes run on the state axis: `.badge-yes`/`.badge-no`/`.badge-unknown`, plus `.badge-status`. The brand colour is coupled across four places (`--marke` in both `:root` blocks, `manifest.theme_color`, the metas, `ACCENT` in `tools/make_icons.py`) — changing it means all four plus regenerating icons, deliberately as a brake. Dark mode is *prepared* (a `@media` block over `:root`) but not built.
- **Under 640 px the map is the full screen; the controls float above it.** ([ADR-008](docs/entscheidungen/ADR-008-karte-im-vollbild-overlay-und-sheets.md), shipped with A-3 on 2026-07-26) There are now **two layout paths** — check every UI change in both. Load-bearing rules: (1) **Overlay elements are siblings of `#map`, never children** — as children Leaflet gets their pointer events and you'd need `L.DomEvent.disableClickPropagation`, which the `L` stub can't test; `#loading`/`#empty` are the deliberate exceptions and are `pointer-events: none`. (2) **The control row is fixed at three elements** (search · filter · feed) — new controls go in a sheet; the old header died of `flex-wrap` growth. (3) **`header` must never get `transform`, `filter` or `will-change`** — it would become the containing block and the `position: fixed` sheets would align to it instead of the viewport. (4) The `<footer>` stays in flow and unobscured; sheets and `#mapControls` sit above its **measured** height (`--footer-h`, set in JS, because large type makes it two lines), never a fixed value. (5) Sheet state is **ephemeral** — no `localStorage`, no URL param. Three traps that cost time and are commented in the code: `#filterPanel` lives inside `header`, which is `pointer-events: none`, so the sheet needs an explicit `pointer-events: auto` or it is visible but click-through; `setPointerCapture` while swiping retargets the following `click` in Chromium, killing the ✕ in the sheet head (track the drag on `window` instead); and **both paths style the same selectors, so specificity decides which wins** — the desktop rules carry `#filterPanel`/`#feed`, so every media-query rule must carry them too (a bare `.sheet-body` loses and silently keeps `display: contents`), and `.controls button` (0,1,1) even beats a bare `.sheet-grip`, which is how the grip and ✕ became white 14-rem boxes. Set `display` **only** inside a path block, never in a shared base rule — a shared value sits later in the file and leaks back to the other path. `#filterPanel` is one node serving both paths — `display: contents` dissolves it on desktop so the chips are flex items of `.controls` again; that also makes the `hidden` **attribute inert** there (an author `display` beats the UA `[hidden]` rule), so the mobile path drives visibility from the media query and JS clears `hidden` and the `role="dialog"` at the breakpoint. The sheet mechanics (`openSheet`) are shared infrastructure and A-2 is their next user.
- **Map pins carry no state at all, and that axis is closed rather than free.** ([ADR-011](docs/entscheidungen/ADR-011-pins-wieder-einheitlich.md), 2026-07-26, reverses [ADR-010](docs/entscheidungen/ADR-010-pin-grammatik-lieferung-und-geschlossen.md) on the day it shipped) A restaurant pin is Leaflet's **default icon** — `L.marker([r.lat, r.lng])` with no options — and Lieferung/Abholung/„jetzt geöffnet" live in popup, badges, chips and filters, in words. Colouring, resizing or dashing the pins again — wholly or partly — needs a **new ADR**, exactly like the third axis ADR-010 was guarding against. Three things the revert nailed down: (1) **the three Leaflet marker images must stay in `CDN_FILES` in `sw.js`** — without them the map is pinless offline, since the unpkg `cacheFirst` rule only fetches them online. (2) **`locateMe()`'s marker stays an `L.circleMarker`** (r 8, fill 0.6, `--marke` via `cssVar()`) — it separates from the teardrops by *shape*; brand red against green is only 1,03 apart, so if restaurant pins ever became circles again it would have to change with them. (3) **The `--zustand-*` tokens are CSS-only now** — `pinTokens()` is gone and `cssVar()` keeps just the one `--marke` fallback, so a `:root` edit can no longer fall silently back to a stale JS copy. What A-5 left behind and must not be re-reverted: `BERLIN_FMT` built once (62,9 → 5,6 ms over 885 evaluations) and the open-state check *behind* the cheap filters, now also short-circuited on `f.open` — 0,60 ms in the default filter. ADR-010's measurements (64/47/774, 427/248/210, contrast 3,32–12,52:1) stay valid as prep work; only its decision is dead.
- **Numbers and contrast ratios cannot answer „does it look good", and that is a real failure mode.** A-5 was measured meticulously, passed 36 browser checks, and was rejected within hours because dark green filled circles read as heavier and busier than the familiar blue teardrop. Its own „Geprüft" section had named the gap — *„not verifiable in the web session: how the circles look with real Leaflet over real tiles"* — and that is precisely where the objection landed. Draw two conclusions, not one: a stated but unverified gap means the work is **unconfirmed, not finished**, so say so in that register; and for anything whose value *is* its appearance, get a real screenshot in front of the product owner **before** the docs get written, because the cost of the revert is mostly documentation. Two further traps this revert exposed: a visual feature can be **worthless in the default view and valuable only in a view few reach** (all 53 default pins were identical green by construction, while the wide view is 774/885 „unbekannt") — check what the *standard* screen gains before building; and when reverting, **separate optics from technique** and keep the invisible wins instead of running one `git revert`.
- **The PWA must never serve stale restaurant data.** ([ADR-006](docs/entscheidungen/ADR-006-pwa-network-first.md)) `restaurants.json` is network-first in `sw.js`; the cache is a fallback for offline only and is surfaced as such in the UI. Never switch it to cache-first — the data is replaced weekly. Same for HTML/manifest. **Bump `CACHE_VERSION` in `web/sw.js` whenever a precached file changes**, and keep the "no `skipWaiting()` on install" rule (the page asks before switching version).
- **Attribution is mandatory (ODbL).** ([ADR-001](docs/entscheidungen/ADR-001-openstreetmap-statt-google-places.md)) "© OpenStreetMap-Mitwirkende" must stay visible in the frontend footer, the JSON `attribution` field, and DATENSCHUTZ.md. Don't remove it.
- **No cookies, no tracking, no analytics, no server-side data collection** is a hard product promise (README + DATENSCHUTZ.md). Geolocation stays browser-only. Don't add anything that breaks this. UI state that should survive a link or a reload goes into **URL query params** via `history.replaceState` (`?delivery=0&open=0&cuisine=thai&q=…`) — never `localStorage`/`sessionStorage`. Write only what deviates from the default, and leave unknown params (e.g. `nearby`) untouched.
